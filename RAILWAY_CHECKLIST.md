# ✅ Railway Deployment Checklist

Quick checklist for deploying Church CMS to Railway.

---

## 📝 Pre-Deployment

### 1. Repository Ready
- [ ] All changes committed to Git
- [ ] Code pushed to GitHub
- [ ] Branch is `master` or your deployment branch

### 2. Configuration Files Present
- [ ] `railway.json` exists ✓
- [ ] `nixpacks.toml` exists ✓
- [ ] `start.sh` exists and is executable ✓
- [ ] `composer.json` and `composer.lock` committed ✓
- [ ] `package.json` and `package-lock.json` committed ✓

### 3. Generate APP_KEY
Run locally:
```bash
php artisan key:generate --show
```
Copy the output (including `base64:`) - you'll need this for Railway variables.

---

## 🚀 Railway Setup

### 1. Create Project
- [ ] Login to Railway (https://railway.app)
- [ ] Click "New Project"
- [ ] Select "Deploy from GitHub repo"
- [ ] Choose your repository
- [ ] Railway detects PHP/Laravel automatically

### 2. Add MySQL Database
- [ ] Click "+ New" in project
- [ ] Select "Database" → "MySQL"
- [ ] MySQL service created automatically
- [ ] Railway injects these variables automatically:
  - `MYSQLHOST`
  - `MYSQLPORT`
  - `MYSQLDATABASE`
  - `MYSQLUSER`
  - `MYSQLPASSWORD`

### 3. Set Environment Variables

Click on web service → **Variables** tab:

#### Essential Variables (REQUIRED):
- [ ] `APP_NAME` = Church CMS
- [ ] `APP_ENV` = production
- [ ] `APP_DEBUG` = false
- [ ] `APP_KEY` = base64:YOUR_GENERATED_KEY
- [ ] `APP_URL` = ${{RAILWAY_PUBLIC_DOMAIN}}
- [ ] `ASSET_URL` = ${{RAILWAY_PUBLIC_DOMAIN}}

#### Database Variables (use Railway references):
- [ ] `DB_CONNECTION` = mysql
- [ ] `DB_HOST` = ${{MYSQLHOST}}
- [ ] `DB_PORT` = ${{MYSQLPORT}}
- [ ] `DB_DATABASE` = ${{MYSQLDATABASE}}
- [ ] `DB_USERNAME` = ${{MYSQLUSER}}
- [ ] `DB_PASSWORD` = ${{MYSQLPASSWORD}}

#### Session & Cache:
- [ ] `SESSION_DRIVER` = database
- [ ] `SESSION_LIFETIME` = 120
- [ ] `SESSION_SECURE_COOKIE` = true
- [ ] `CACHE_DRIVER` = database
- [ ] `QUEUE_CONNECTION` = database

#### Production Settings:
- [ ] `APP_TIMEZONE` = UTC (or your timezone)
- [ ] `TRUSTED_PROXIES` = *
- [ ] `LOG_CHANNEL` = stack
- [ ] `LOG_LEVEL` = error

#### Optional (Payment Gateways):
- [ ] `PAYSTACK_PUBLIC_KEY` (if using card payments)
- [ ] `PAYSTACK_SECRET_KEY`
- [ ] `HUBTEL_CLIENT_ID` (if using mobile money)
- [ ] `HUBTEL_CLIENT_SECRET`
- [ ] `TWILIO_SID` (if using SMS)
- [ ] `TWILIO_AUTH_TOKEN`
- [ ] `TWILIO_PHONE_NUMBER`

## 🆘 Common Issues & Fixes

### Build Fails
1. Check `composer.lock` is committed
2. Check `package-lock.json` is committed
3. Review build logs for specific errors
4. Verify PHP version compatibility

### Database Connection Error
1. Ensure MySQL service is running
2. Check database variables use `${{MYSQL...}}` syntax
3. Verify MySQL and web service are in same project
4. Check Railway logs for connection errors

### 500 Errors
1. Verify `APP_KEY` is set correctly
2. Check `APP_DEBUG=false`
3. Review Railway logs for specific error
4. Verify storage permissions (handled by start.sh)

### Assets Not Loading
1. Verify `ASSET_URL=${{RAILWAY_PUBLIC_DOMAIN}}`
2. Check `npm run build` succeeded in logs
3. Verify `public/build` directory exists
4. Check browser console for 404 errors
